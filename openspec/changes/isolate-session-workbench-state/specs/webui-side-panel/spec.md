## MODIFIED Requirements

### Requirement: Side panel layout in single-session view

Web UI 单会话视图 SHALL 提供文件与变更导航及详情页签；其他布局按现有规则显示。系统 MUST 按会话保存文件页签、排序、选中项、编辑与浏览位置、文件树缓存和展开、列表栏目、比较基线、详情显示、最大化和尺寸。同工作区或相同 cwd 不得共享这些会话工作状态。

#### Scenario: 单会话视图渲染右侧面板
- **WHEN** 用户进入单会话视图并展开右侧面板
- **THEN** 显示该会话的文件/变更导航和详情页签，宽度使用该会话保存值或默认值

#### Scenario: 切到 4 宫格隐藏面板
- **WHEN** 用户从单会话视图切换至不显示侧面板的布局
- **THEN** 面板不占用该布局空间，其会话工作状态保留供返回时恢复

#### Scenario: tab 切换零延迟
- **WHEN** 用户切换文件/变更栏目或已有详情页签
- **THEN** 立即呈现该会话缓存的视图；需要补充数据时在该会话内加载，不借用其他会话的视图状态

#### Scenario: 切 session 时面板状态保留
- **WHEN** 用户在相同 cwd 的 A/B 会话之间切换
- **THEN** 各自保留并恢复自己的缓存、展开、选中和栏目；B 不继承 A 的面板状态

#### Scenario: cwd 真变时整面板 reset
- **WHEN** 用户进入尚无缓存的另一 cwd
- **THEN** 该目录从初始状态展示，不显示旧目录残留；原会话和目录的状态仍独立保存，再次返回可恢复

#### Scenario: 同工作区会话独立恢复
- **WHEN** A 打开五个页签，切到从未打开页签的 B，B 再打开两个页签并切回 A
- **THEN** B 首次为空，A 恢复原五页签及其顺序与活动项；再次进入 B 只显示 B 的两个页签

#### Scenario: 关闭和重排独立
- **WHEN** A 与 B 都打开同一个文件，B 关闭、关闭其他、关闭全部或拖动排序
- **THEN** A 的页签集合、顺序和活动项保持不变

#### Scenario: 文件树和面板状态独立
- **WHEN** A 展开目录、选中文件、滚动列表、调整尺寸或最大化详情后切到 B
- **THEN** B 恢复自己的状态，返回 A 恢复 A 的状态，跨工作区往返亦然

#### Scenario: Git 缓存和基线独立
- **WHEN** 同 cwd 的两个会话选择不同基线并分别加载列表与 diff
- **THEN** 各会话恢复各自基线与缓存，异步回包不能覆盖另一个会话，同一会话的导航与详情使用一致结果

#### Scenario: 切换未保存文件
- **WHEN** 当前会话文件有未保存修改并请求离开
- **THEN** 显示“取消 / 不保存 / 保存”；取消保持当前位置，不保存丢弃后切换，保存成功后切换，失败保留修改且不切换

#### Scenario: 新建入口交接
- **WHEN** 用户从新建入口创建正式会话
- **THEN** 临时工作状态只交给该新会话，后续新建入口独立，已有会话不继承临时状态；聊天输入草稿遵守原会话恢复规则

#### Scenario: 晚到异步回调
- **WHEN** 会话 A 的文件、目录或 Git 请求在切到 B 后完成
- **THEN** 回包只更新 A 的缓存或被取消，不修改 B 的展示和编辑状态
