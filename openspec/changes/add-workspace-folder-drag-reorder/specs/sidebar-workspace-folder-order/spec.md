## Purpose

让用户通过拖动或键盘安排侧栏工作区文件夹的位置，并清楚看到正在移动的分组及目标位置。排序以工作区身份持久化，保证刷新、重新打开桌面界面和工作区元数据变化后仍可恢复用户安排。

## ADDED Requirements

### Requirement: 文件夹分组可以拖动排序
侧栏 SHALL 允许从工作区标题行拖动文件夹，在其他工作区分组之前或之后放下；任务所属工作区及任务内部顺序 MUST 保持不变。

#### Scenario: 跨展开分组移动文件夹
- **WHEN** 用户拖动一个文件夹经过其他已展开或已收起的工作区
- **THEN** 图标和名称浮层跟随指针，原分组淡化并保留占位，插入线仅显示在工作区分组之间
- **THEN** 放下后整个源分组移动到指示位置，保留各组展开状态和会话归属

#### Scenario: 取消与普通点击
- **WHEN** 用户按 Escape、丢失窗口焦点、取消指针或在列表外释放拖动
- **THEN** 不提交排序，移除浮层与插入线，并恢复指针状态
- **WHEN** 用户仅点击文件夹或其菜单、新建任务、重命名输入框
- **THEN** 执行现有控件行为，拖放结束的合成点击不会展开收起文件夹

### Requirement: 工作区顺序可靠持久化
系统 SHALL 按工作区身份保存排序并从列表接口恢复；保存失败 MUST 恢复已确认顺序并提示错误，排序请求 MUST 是当前可见工作区的完整唯一排列。

#### Scenario: 刷新和桌面重启
- **WHEN** 用户成功保存顺序后刷新或重新启动桌面端，或工作区被重命名
- **THEN** 文件夹恢复保存的相对顺序，桌面端口变化不影响恢复

#### Scenario: 工作区集合变化
- **WHEN** 保存后新增、隐藏或重新显示工作区
- **THEN** 已排序的可见工作区保持相对顺序，新工作区追加，隐藏工作区不显示，重新显示的工作区保留其已保存位置
- **WHEN** 提交的排列含重复或未知身份，或遗漏当前可见工作区
- **THEN** 拒绝请求且不改变已保存顺序

#### Scenario: 保存失败或刷新竞争
- **WHEN** 保存失败，或旧轮询请求在拖放提交期间完成
- **THEN** 失败会恢复排序并显示错误，旧轮询不会覆盖待保存或刚保存的排序

### Requirement: 排序支持键盘和滚动
侧栏 SHALL 支持聚焦文件夹后使用 Alt+上箭头或 Alt+下箭头调整位置，并在拖动接近滚动区域边缘时自动滚动；主题、窄窗口和减少动态效果设置下反馈 MUST 可辨识。

#### Scenario: 键盘调整
- **WHEN** 聚焦文件夹后按 Alt+上箭头或 Alt+下箭头
- **THEN** 文件夹向对应方向移动一位并持久化，焦点仍保留在该文件夹

#### Scenario: 长列表拖动
- **WHEN** 用户在滚动区域顶部或底部附近拖动
- **THEN** 列表自动滚动且插入位置随布局更新，减少动态效果时仍提供即时浮层和插入线反馈
