## Purpose

允许用户在已有会话的完整对话记录以用户消息或明确的用户中断标记结束时，通过空输入发送重新请求对应用户消息，保持结构化输入与模型角色顺序，并防止过期界面状态导致错误重发。

## ADDED Requirements

### Requirement: 空输入仅允许重试完整记录末尾的用户消息

系统 SHALL 仅在会话已加载且空闲、输入没有文字或新增附件/上下文、完整 transcript 最后一个条目是已持久化用户消息或明确的用户主动中断标记时启用空输入发送。按钮和 Enter SHALL 使用相同规则。

#### Scenario: 末尾用户消息
- **WHEN** 已加载空闲会话的完整 transcript 以用户消息结束，输入为空或只有空白
- **THEN** 点击发送或按 Enter 重试该用户消息

#### Scenario: 非用户内容在用户消息之后
- **WHEN** 用户消息之后存在 assistant、推理、tool、system、error 或其他可见条目，包括空 assistant 条目，且完整 transcript 末尾没有明确的用户主动中断标记
- **THEN** 空输入发送保持禁用，不得跳过条目查找更早的用户消息

#### Scenario: 会话不可重试
- **WHEN** 会话无历史、未加载、加载失败、只读、正在运行、提交中或缺少末尾消息身份
- **THEN** 空输入不触发重试，也不进入排队或新建会话路径

#### Scenario: 输入含新内容
- **WHEN** 用户输入文字或新增附件/上下文
- **THEN** 使用正常发送或排队流程

### Requirement: 重试复用原始输入并保持角色序列

系统 MUST 使用原始用户消息重新请求模型，保留附件、上下文及展示信息。模型历史末尾仍为该用户时保留消息身份，不增加重复 user 记录；主动中断前已有 assistant/tool 记录时保留已有记录并以新身份追加原始用户内容。

#### Scenario: 富文本或附件消息重试
- **WHEN** 末尾用户消息含已展开 skill、附件或上下文
- **THEN** 模型收到原始结构化内容，transcript 保留原 user 记录且后续响应追加在其后

### Requirement: 后端拒绝过期或并发重试

系统 MUST 在接受重试时及执行时校验完整 transcript 末尾和指定用户身份符合对应重试规则，接受动作必须与任务队列状态校验串行化。

#### Scenario: 界面状态过期
- **WHEN** 点击时后端已有后续消息，或请求携带的用户消息身份不再匹配
- **THEN** 拒绝重试，不追加消息且不调用模型

#### Scenario: 重复点击或已有排队任务
- **WHEN** 重试已接受或已有其他活动/排队任务
- **THEN** 后续重试被拒绝，单次操作最多触发一个模型回合

#### Scenario: 请求期间切换会话或编辑草稿
- **WHEN** 重试请求尚未完成，用户切换会话或输入下一条消息
- **THEN** 原会话请求回执不改变新会话的忙碌状态，也不清除新草稿

### Requirement: 用户中断后可直接重发

系统 MUST 以持久化的结构化用户中断标记判断重发资格，并等待后端实际结束当前回合。

#### Scenario: 中断发生在输出之前
- **WHEN** 用户停止回合，后端确认结束，模型历史仍以原用户消息结束
- **THEN** 空输入重发复用原用户消息，不产生相邻 user

#### Scenario: 中断发生在部分回复或工具结果之后
- **WHEN** 用户停止回合，后端确认结束，已有部分回复或工具结果
- **THEN** 保留已有输出并允许空输入重发；模型历史已有 assistant/tool 时追加原始结构化用户内容，否则复用原用户消息

#### Scenario: 中断确认前或中断之后又有新记录
- **WHEN** 后端尚未确认中断，或中断标记后出现新消息、错误或活动任务
- **THEN** 不允许根据旧中断标记重发

#### Scenario: 恢复中断历史
- **WHEN** 重新加载的完整 transcript 以有效用户中断标记结束
- **THEN** 恢复同样的重发资格；普通中断字样或插话标记不得获得该资格
