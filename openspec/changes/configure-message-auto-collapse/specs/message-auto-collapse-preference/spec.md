## ADDED Requirements

### Requirement: 会话样式设置与持久化
系统 SHALL 在外观设置的一级分组“会话”中提供“消息自动折叠”，默认开启，选项标题使用普通字重。选择 SHALL 经现有外观偏好机制持久化并立即生效。

#### Scenario: 旧配置与首次打开
- **WHEN** 配置中没有 `message_auto_collapse`
- **THEN** 开关开启，现有自动折叠行为保持不变

#### Scenario: 保存关闭状态并重启
- **WHEN** 用户关闭消息自动折叠后重新打开应用
- **THEN** API、Desktop 首帧与界面均恢复关闭状态，修改其它外观项不重置该值

#### Scenario: 无效输入及保存失败
- **WHEN** 偏好 API 收到非布尔值或持久化失败
- **THEN** 无效输入被原子拒绝，保存失败回滚至上次确认的偏好

### Requirement: 主会话与子代理共享折叠策略
主会话与子代理 SHALL 共用同一投影和显示策略。关闭自动折叠时 SHALL 显示所有消息正文，不生成可折叠的工具段或完成轮次摘要，只保留单个工具调用自身的折叠交互。

#### Scenario: 完成轮次与历史消息
- **WHEN** 关闭状态下展示包含过程回复、多个工具调用与完成总结的轮次
- **THEN** 过程回复、工具行及完成总结按序显示，不出现“已处理”大折叠，工具配对去重仍生效

#### Scenario: 实时会话及特殊分组
- **WHEN** 关闭状态下工具正在运行或会话含图片、子代理、系统通知
- **THEN** 运行状态持续可见，图片与子代理内容直接显示，子代理入口可用，系统通知正文展开

#### Scenario: 来回切换
- **WHEN** 用户从关闭切回开启
- **THEN** 当前消息立即恢复原有折叠路径，原始消息数据不被修改
