## ADDED Requirements

### Requirement: 离开未保存文件前确认

系统 MUST 在用户离开含未保存修改的文件编辑现场前显示确认对话框，按钮按“取消”“不保存”“保存”排列。切换文件或详情页签时检查即将离开的文件，切换会话、工作区、返回首页及前进后退时检查当前预览区域的未保存文件。关闭文件 SHALL 复用相同决定流程。

#### Scenario: 取消切换
- **WHEN** 用户编辑文件后切换详情页签或会话，并选择“取消”或按 Esc
- **THEN** 原文件、编辑内容、活动会话及导航历史保持不变

#### Scenario: 不保存后切换
- **WHEN** 用户选择“不保存”
- **THEN** 系统丢弃即将离开范围内的未保存修改，再执行最初请求的切换，且不写入磁盘

#### Scenario: 保存后切换
- **WHEN** 用户选择“保存”且所有相关文件保存成功
- **THEN** 系统完成原切换，文件的未保存标记清除，保存过程中禁止重复提交

#### Scenario: 保存失败
- **WHEN** 保存发生版本冲突、网络错误或其他失败
- **THEN** 系统保留原位置与未成功保存的修改，在弹窗内显示错误并允许重新选择；不得继续切换

#### Scenario: 相同目标与干净文件
- **WHEN** 用户重复激活当前文件，或离开范围内没有未保存修改
- **THEN** 系统不弹出未保存确认

#### Scenario: 工作区导航尚未执行
- **WHEN** 用户请求进入其他工作区且当前文件未保存
- **THEN** 系统在激活目标工作区、重定向页面或修改会话导航状态之前等待决定，取消不触发这些动作

#### Scenario: 自动页签切换与重复导航
- **WHEN** 原生浏览器产生新的自动激活请求或确认期间再次收到导航请求
- **THEN** 未保存文件不能被直接切走，已有确认目标不被替换或同时执行

#### Scenario: 聊天输入草稿保持独立
- **WHEN** 用户确认文件修改并切换会话
- **THEN** 聊天输入框仍按照各自会话的草稿恢复，文件确认不会清空或覆盖聊天输入草稿
