## Why

右侧文件编辑器目前只在关闭页签时提示未保存修改，切换文件、预览类型或会话时会直接离开编辑现场。用户要求把离开前的决定交给自己，取消时留在原处，选择保存或不保存后才继续原操作。

## What Changes

- 复用关闭文件的确认与版本校验保存流程，在切换详情页签、打开另一文件、切换会话/工作区、返回首页及前进后退之前拦截未保存修改。
- 统一提示用户存在未保存修改，按钮按“取消 / 不保存 / 保存”排列；取消不切换，不保存丢弃受影响修改后继续，保存成功后继续，失败保持原位置和修改。
- 同一文件重复激活不提示；自动打开浏览器页签不能绕过正在编辑的文件或覆盖已有确认目标。
- 保留聊天输入框已有的会话级草稿机制，本变更不迁移其他缓存。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `webui-side-panel`: 增加未保存文件修改的离开确认与取消导航约束。

## Impact

涉及 `ChatView` 的预览操作与关闭弹窗、`App` 和 `Sidebar` 的导航入口，以及可测试的未保存确认控制器。保存继续走现有 `saveEditableFileDraftBatch` 与文件版本校验 API；无新增后端协议或依赖。
