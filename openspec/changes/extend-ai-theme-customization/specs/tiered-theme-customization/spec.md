# Tiered theme customization

## ADDED Requirements

### Requirement: 三组初始问题
ai-theme SHALL 在生成前询问定制程度、主题模式、风格基座，并复用用户已明确的答案。

#### Scenario: 初次定制
- **WHEN** 用户开始定制且尚未选择范围
- **THEN** 提供快速/高级/深度、位图/矢量图/自带贴图、白天/黑夜/不限三组单选，不把未选答案当作确认

### Requirement: 按范围询问细节
技能 SHALL 提供三档建议和其他输入，询问首页输入框透明度及已选择背景区域的主色与透明度。

#### Scenario: 快速与高级范围
- **WHEN** 用户选择快速或高级定制
- **THEN** 快速只询问主页细节，高级增加会话细节，透明度转换为 0..1 opacity 且不影响文字本身

### Requirement: 无生图预览
技能 SHALL 支持 HTML 与 ACECode Browser 预览，矢量图和自带贴图模式 MUST NOT 调用生图工具。

#### Scenario: 无生图模型
- **WHEN** 生图工具或模型不可用
- **THEN** 使用本地 HTML 展示背景、颜色和透明度，保留人工确认流程；未完成的素材不得用占位框图冒充最终主题

### Requirement: 分离会话与用户消息背景
系统 SHALL 独立保存、校验和应用主页、会话和用户消息背景，并兼容原有三文件主题包。

#### Scenario: 深度主题交付
- **WHEN** 用户确认带会话和用户消息背景的主题并安装或导入导出
- **THEN** 全部声明资源及外观参数保持一致，聊天卡片图片只影响用户消息，助手回复不使用该图片

#### Scenario: 资源改变或无效
- **WHEN** 任一确认后的背景资源改变，或包内存在未声明/缺失资源或无效透明度
- **THEN** 安装拒绝并要求修复或重新确认，不发布不完整主题

#### Scenario: 切换到旧主题
- **WHEN** 用户从多背景主题切换到未声明附加背景的主题
- **THEN** 清理附加图片及透明度覆盖，恢复旧主题原有表现
