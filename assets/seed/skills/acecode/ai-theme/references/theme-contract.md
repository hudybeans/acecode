# ACECode 主题数据与确认

主题由主页独立背景、缩略图、28 色定义、可选会话/用户消息背景和外观设置组成。`theme_create` 负责会话草稿、人工确认、资源校验、安装与打包；技能只负责设计和调用工具。

## 颜色

`mode` 只能是 `light` 或 `dark`。`colors` 恰好包含以下 28 个键；值使用 `#RRGGBB`，不要传 CSS 变量、透明度、渐变或额外键。完整示例见 `palette-example.json`，它可作为结构起点，颜色必须适配用户本次要求。

| 键 | 界面用途 |
| --- | --- |
| `bg` | 主工作区基础背景 |
| `surface` | 输入框、卡片及设置面板 |
| `surface-alt` | 次级面板和输入控件 |
| `surface-hi` | 悬停和突出表面 |
| `shell-hi` | 侧栏和窗口区域的突出表面 |
| `shell-bg` | 侧栏及窗口底色 |
| `border` | 主要边框 |
| `border-soft` | 弱分隔线 |
| `fg` | 正文及主标题 |
| `fg-2` | 次要文字 |
| `fg-mute` | 辅助说明和占位文字 |
| `accent` | 链接、焦点和主强调色 |
| `accent-bg` | 强调区域底色 |
| `accent-soft` | 弱强调区域底色 |
| `ok` | 成功文字及图标 |
| `ok-bg` | 成功状态底色 |
| `ok-border` | 成功状态边框 |
| `warn` | 警告文字及图标 |
| `warn-bg` | 警告状态底色 |
| `danger` | 错误与危险操作文字 |
| `danger-bg` | 错误状态底色 |
| `code-bg` | 代码块背景 |
| `code-fg` | 代码文字 |
| `code-line` | 保留的代码辅助色；当前文件行号实际使用 fg-mute 混合透明度，不能承诺由此键直接控制 |
| `selection` | 选中区域背景 |
| `on-selection` | 选中区域文字 |
| `send-bg` | 发送按钮背景 |
| `send-fg` | 发送按钮图标 |

正文与 `surface`、`bg` 的对比尽量达到 4.5:1；发送按钮前景与背景、错误及成功状态也要清楚可辨。主色应出现在强调、选择和按钮中，配合低饱和表面承载文字。主题主色不能抹掉成功、警告、错误的区别。

## 代码阅读舒适度

代码查看、编辑和会话代码块默认优先保证高对比度：**实际代码背景为浅色，文字必须为深色；实际代码背景为深色，文字必须为浅色。** 不根据整套主题的 mode 推断代码底色；浅色主题可以保留深底浅字的代码面板。颜色可以带主题色相，但不能为了柔和、低饱和或统一主色而降低代码可读性。

- 提交色系前，检查 `code-bg` / `code-fg` 的明暗方向，普通代码文字以至少 4.5:1 为默认对比目标；源码卡片还要检查其实际使用的 `surface` / `fg`。颜色反差不能只凭名称判断。
- 用包含普通文字、关键词、字符串、数字、注释的真实代码样例检查实际渲染，并检查行号和选中文字。修改 `code-fg` 不会重染全部语法高亮；当前部分 token 色由渲染器固定，文件行号使用带透明度的 `fg-mute`。调整这些共享颜色时还要复查其它文字区域。
- 现有高亮中有面向深色代码底色的固定配色。选择浅色代码面板时必须核对实际 token，而不是仅把普通文字变深；不清楚或不可读时先调整为可实现的高对比方案。若当前渲染器限制仍使某类文字难读，说明具体限制，不能宣称已全部通过，不能靠原型虚构支持或修改应用源码绕过。
- 默认直接遵循规则，不新增首轮问题。用户要求冲突配色时，指出具体代码区域的阅读影响并给出高对比替代；只有用户明确坚持原方案才允许该范围的例外。用户已明确表达这种坚持时直接记录，不重复追问。沉默、笼统的“柔和风格”、选择主题主色或普通色系确认均不等于同意打破规则。
- 将用户明确坚持的原话、涉及的代码区域和颜色记录在任务需求备注中，并在色系与原型确认时展示实际效果。例外不自动扩展到其它区域；沿用正常确认流程，不新增 `syntax-*`、对比度豁免等未支持的 colors/appearance/theme.json 字段，也不改变已有主题参数。

## 图标、首页标题与通顶

`appearance` 与 `colors` 同级，是可选对象。原有三个参数保留，并增加下文的背景/透明度参数。不要把它们加入 28 色对象，也不要传 `null`、未知键、CSS 或字符串形式的布尔/数值；空对象 `{}` 表示不提供覆盖。

| 键 | 类型与效果 | 省略时 |
| --- | --- | --- |
| `logo_color` | `#RRGGBB`，首页静态/动态图标和侧栏图标的主色，保留原图标形状及白色字形 | 保留原图标 |
| `home_title_color` | `#RRGGBB`，首页“我们该做什么？”及带项目名的标题颜色 | 使用 `colors.fg` |
| `extend_to_titlebar` | boolean，首页壁纸延伸至主内容列标题栏，侧栏保留自己的底色 | 新建 AI 主题不通顶 |

深色模式通顶时，右侧面板按钮和窗口控制按钮使用白色，关闭按钮保留红色悬停；浅色通顶使用主题前景。设计顶部背景时按本次 `mode` 和按钮前景保证可读，不自动推断图片明暗。非首页或没有有效背景时使用正常标题栏。旧 EVA 缺省设置继续使用已有的通顶与白色按钮。

色系确认同时绑定这些参数。修改、增加或移除参数都需要重新确认色系并制作匹配的原型；`palette` 是整份替换，省略 `appearance` 会移除此前的全部覆盖。

## 背景与透明度

以下参数同样放入 appearance；所有 opacity 是有限 0..1 数值（0 完全透明、1 不透明）。问用户的是透明度百分比，写入前转换为 `1 - 百分比/100`。文字、图标和按钮不随背景变透明。

| 参数 | 用途与缺省 |
| --- | --- |
| `home_composer_opacity` | 首页文本框底色，缺省 0.95，与旧主题相同 |
| `home_background_color` / `home_background_opacity` | 首页背景底色/图片不透明度，缺省 colors.bg / 1 |
| `session_background_color` / `session_background_opacity` | 会话背景底色/图片不透明度，缺省 colors.bg / 1 |
| `user_message_background_color` / `user_message_background_opacity` | 仅用户消息气泡底色/图片不透明度，缺省 colors.accent-bg / 1 |

三个背景色为 #RRGGBB。会话/用户消息未提供独立素材时不增加背景效果，旧主题保持原样。修改任一新参数时必须保留未修改的 logo_color、home_title_color、extend_to_titlebar，并重走确认。

所有背景图片保持长宽比例。首页/会话图默认 cover 铺满对应区域；会话图不限制在居中横幅。所有用户消息图统一显示为 720 CSS px 宽、高度等比自动计算（720px auto），右下对齐（right bottom）、不重复；短消息、长消息和宽窄窗口仅改变裁切范围，图案大小保持一致。气泡超出图片高度的部分显示 user_message_background_color。素材顶部底色必须与该颜色一致，或用透明装饰露出它，避免接缝。图像透明度只作用于图层，不淡化消息文字；纯色遮罩仍铺满气泡，双层 background-size 为 100% 100%, 720px auto。720 CSS px 是界面显示宽度，不是素材导出尺寸；用户约定的素材导出尺寸记录在需求中，不新增未支持的 appearance 尺寸键。

## 调用顺序

所有示例中的占位 ID 和路径要替换成工具实际结果。`colors` 使用完整对象，不要发送省略号。

1. `{"action":"status"}`：查看本任务草稿；有 ID 时可传 `draft_id` 精确查询。
2. `palette`：传 `action`、`name`、`mode`、完整 `colors` 及已展示的可选 `appearance`；仅更新已有草稿时传 `draft_id`。先展示色表、图标主色、首页标题色和通顶设置，工具再通过原生问答请求「确认色系」或「修改」。修改颜色或外观设置会使原来的确认失效。
3. `{"action":"prototype","draft_id":"实际 ID","background_path":"背景绝对路径","preview_path":"界面原型绝对路径"}`：已确认色系后才可调用；先展示图片，再让工具请求「确认原型并生成」或「修改」。工具保存本次资源副本和校验和。
   高级/深度附加 `session_background_path`，深度附加 `user_message_background_path`。素材是全量替换，未提交的可选背景会移除；只修改一张图时也要带回其它需保留的素材。所有素材参与原型确认，变更后不能复用旧确认。
4. `{"action":"install","draft_id":"实际 ID"}`：只使用已确认的资源。安装时不接受替换图片、颜色或 `confirmed`。同一已安装草稿重试返回已有主题。

任何一步都以工具的 `stage`、`next_action` 和确认结果为准。`palette`、`prototype` 返回的 `confirmed` 只可读取，不可作为输入；普通工具调用成功不等于用户已确认。取消、修改、超时和无人值守都不能用聊天中的自述代替确认。

## 文件边界

- `background_path` 是无 UI、可独立使用的主页背景；会话和用户消息素材同样不得含示意控件。`preview_path` 是带布局的效果图，也可为 HTML 在 Browser 中的真实截图。SVG/CSS 先用 Browser 渲染为 PNG；不直接提交 HTML/SVG 或只改扩展名。最终 PNG 转换和缩略图由安装工具处理。
- 主题标识由工具生成在 `ai-` 命名空间，保留 `blue`、`orange`、`eva-01` 等现有主题。
- 基础包仍为 `theme.json`、`background.png`、`thumbnail.png` 三个根文件；可选增加 `session-background.png` 和 `user-message-background.png`，分别由 theme.json 的 session_background、user_message_background 描述大小和 SHA-256。只有声明的资源可入包，总体不超过 16 MiB。不要自己组装 ZIP、计算安装版本或写主题目录。
- 安装结果包含实际位置及 `theme_created` 元数据。实时 Web/Desktop 任务使用该事件刷新并应用，打开历史记录不会再次应用主题。
