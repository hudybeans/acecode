# 背景与界面原型

本文件只适用于用户选择位图且生图工具/模型可用的情况。矢量图和用户贴图不调用生图工具；无生图模型时按 browser-preview.md 使用 HTML + Browser。位图只调用 ACECode 的 `image_generate`，使用 `prompt`、`quality`、`reference_image_paths`，不要套用其他宿主参数。用宽幅、横向桌面构图等描述比例，不传未支持的像素尺寸。默认 `quality="standard"`，每次最多引用 5 张本地图片。

## 首页参考图

本技能随包提供用户指定的两张 ACECode v0.9.14 首页截图，按本次已经确认的 `mode` 选用：`light` 使用 `assets/acecode-home-light.png`，`dark` 使用 `assets/acecode-home-dark.png`。保持对应模板的窗口比例、侧栏、Logo、标题、输入区、工作区选择和四个功能卡片的位置。旧的 `assets/acecode-home-reference.jpg` 仅保留兼容，不再作为新主题的默认底图。

从当前技能激活上下文给出的 `SKILL.md` 绝对路径取父目录，再拼接该资源的相对路径；不要使用开发机的仓库地址或假设当前工作目录就是技能目录。如果通过 `skill_view` 自动发现而没有绝对路径，仅在当前 ACECode 技能目录中定位 `acecode/ai-theme/SKILL.md`，核对内容后解析资源。找不到时说明缺失的参考资源并保留草稿，不编造路径。

图片资源使用 `show_image({"image_path":"资源的实际绝对路径"})` 查看；不要用 `skill_view` 将 JPEG 当作文字读取。用户提供更接近当前版本的 ACECode 截图时优先采用用户截图，保留其真实布局；把其他产品的主题图仅作为配色或人物构图参考。

## 先做独立背景

新图省略 `reference_image_paths`；用户提供角色或画风参考时传真实参考路径。把用户主题对象、主辅色、风格和明暗要求写入提示词，并包含这些构图要求：

> 制作可用于 ACECode 桌面首页的独立背景。保持宽幅构图，主角完整的视觉重心安排在右侧，中心和左侧留出平静的低对比区域，供输入框和界面文字覆盖。主色与已确认色系一致。只画背景和主题主体，不画软件窗口、文字、按钮、Logo、边框或水印。光线与透视统一，主体边缘清楚，避免把关键面部、头饰或武器切在画面边缘。

该构图是人物主题的默认方向；用户指定其他主体位置时跟随用户，并保留对应内容区留白。不要将 EVA、动漫或紫色固定为所有主题的要求。

所有主题图片只做等比适配。首页和会话背景默认等比 cover 铺满对应区域，提示词明确“画面与底色覆盖整个画布，不留上下边框或空白条带，不画居中横幅”；只有用户明确约定尺寸或构图时才遵守该例外。不能用非等比拉伸把模型结果凑成目标尺寸。

若场景包含天空，检查云层有大小与厚薄变化、远近层次和一致光源；避免重复棉花团、对称云环、塑料质感及贴纸轮廓。动漫场景使用可信的手绘云体块，不把云朵强制处理成照片。用户要求修改云朵时引用当前背景，只修改天空并保留主体和构图。

记录 `image_generate` 返回的实际保存位置为背景路径。附件已经显示，不要立即又重复嵌入一次。

## 再做 ACECode 界面原型

代码区域遵循 [代码阅读舒适度](theme-contract.md#代码阅读舒适度)：浅底深字、深底浅字，保持高对比；主题主色和柔和风格不能覆盖该默认规则。原型中出现代码时保留这条要求，只有用户明确坚持的例外才按记录处理。生成图只能表达视觉意图，最终仍需用真实代码文本检查当前渲染器，不能用模型重绘的高亮证明代码可读性已通过。

高级/深度同时准备会话背景，采用低对比、适合长时间阅读的构图；深度再准备用户消息卡片底图，在右下裁切区域保留可辨认的装饰。每张图独立保存。聊天卡片只作用于用户发送的消息，不把 AI 回复或工具卡片画成有同样背景。准备好位图素材后也可用 HTML + Browser 合成精确布局预览，避免重绘文字。

用户消息素材的提示词还必须说明：图案位于右下角，所有消息均将完整底图显示为 720 CSS px 宽、高度等比自动计算（720px auto），right bottom、不重复；短气泡只裁切右下部分，长消息和窄窗口也不改变图案大小，不按单条消息宽度重新缩放。图片比长消息气泡矮时，剩余部分由 user_message_background_color 补齐。因此素材顶部采用与该 HEX 完全一致的平坦底色，或输出透明背景的独立装饰，不做延伸到顶部的异色渐变。最终 PNG 应实看顶部颜色；分别验证短气泡、长气泡和窄屏的装饰大小一致，不能只检查一张固定大小的卡片。

`reference_image_paths` 按顺序包含：与 `mode` 匹配的 ACECode 深色或浅色首页模板、独立背景。提示词明确两张图的职责，并提供确认后的颜色角色与 HEX：

> 图一是必须保留的 ACECode 软件界面，图二是要应用的背景。输出一张完整的 ACECode 主题效果图。严格保留图一的窗口、侧栏宽度、导航层级、ACECode 品牌、主标题、输入框、工作区选择和功能卡片的位置、数量及文字，不增加新模块。把图二作为主内容区的背景，按已确认色表重着色侧栏、表面、正文、焦点和发送按钮。面板保留足够遮挡，让文字可读；主题主体位于右侧且与输入区协调。效果要能用背景图片及这些颜色实现，不增加主题系统不支持的动效、3D 窗口或控件形状。

在同一提示词中补充完整、已确认的 `appearance`：保留 `logo_color`、`home_title_color`、`extend_to_titlebar`，再添加各背景主色、图片透明度和首页文本框透明度。图标保持原形状与白色字形；标题使用独立色，正文不变。不要因为新增参数省略旧参数。图片与输入框透明度只影响背景层，不淡化文字和按钮；缺省按主题契约解释。

`extend_to_titlebar=true` 时，主内容列使用同一张连续壁纸延伸到标题栏，侧栏保持自身底色；`false` 或新建主题未设置时，标题栏保留独立底色。深色模式通顶右侧按钮必须为白色，关闭按钮保留红色悬停；浅色通顶使用主题前景。选择与本次 `mode` 和按钮前景匹配的顶部背景，不能靠原型图虚构最终系统不支持的按钮颜色。

这是用于用户确认的效果图，不把模型重绘的 UI 像素作为最终背景。记录另一个实际保存位置为原型路径。

检查后再发起原型确认。用户只改背景时，先修订背景，再引用修订背景重新生成匹配的原型；用户只改配色、图标色、首页标题色或通顶设置时，返回色系确认，再更新原型。最终提交给 `prototype` 的两条路径必须对应用户正在看的同一版方案。
